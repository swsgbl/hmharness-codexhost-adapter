## Textual Item Completion Repair

CodexHost 0.12.1 enforces an invariant in `app/host-runtime.mjs`: the text in a completed `agentMessage` or `reasoning` Item must equal the text accumulated through `text.append` updates. The HMHarness bridge can stream interim assistant progress during multi-tool work and later return an authoritative final `result.text` that differs from that progress.

The previous plugin mismatch branch reused the streamed Item ID while replacing its text with the authoritative final text. Host rejected that completion with:

```text
Host textual Item completion does not match its append updates
```

The child delegation and bridge could complete, but the parent Host turn remained in a Thinking state. This was a local adapter protocol defect, not a CodexHost delegation or bridge failure.

The repaired `#succeedTurn` behavior is:

1. If the final text equals the accumulated stream text, complete the existing Item unchanged.
2. Otherwise, complete the streamed Item using exactly the accumulated stream text.
3. Start and complete a second `agentMessage` Item for the authoritative final text.
4. Complete the Turn with both snapshots.

This preserves streaming progress and satisfies the official Host invariant.
