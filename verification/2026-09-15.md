# CodexHost 0.8.2 HMHarness validation

Date: 2026-09-15, Asia/Shanghai.

## Scope

- Update to the official CodexHost `0.8.2` Windows installer distribution.
- Adapt HMHarness to the 0.8.2 controller/renderer/plugin layout without another upstream merge.
- Preserve the dedicated HMHarness icon instead of falling back to Antigravity.
- Verify model selection, a real UI request, final UI cleanup, bridge cleanup, and Windows launch-environment restoration.

## Current Versions

- Official installer: `0.8.2`, reported by `%LOCALAPPDATA%\Programs\codexhost\app\codexhost-distribution.json` and the launcher executable file version.
- Public npm CLI on PATH: `@codexhost/cli@0.8.0`. This wrapper version is not the Desktop host version and must not be used as the adaptation target.
- Codex CLI: `0.154.0`.
- Codex Desktop: `26.908.8172.0`.
- HM bridge: `@hmharness/codexhost-bridge@0.6.5`.
- Upstream tag: `v0.8.2`, peeled commit `969fbde59a927250448854b1ad4c78a2854cd4c5`.

- Plugin bundle: `snapshots/codex-host-runtime/0.8.2/plugin`.

## Launcher Fallback

On this Windows Insider/MSIX machine, Codex Desktop did not inherit the 0.8.2 environment injection. The verified shortcut chain is:

```text
C:\Users\hongfu\Desktop\CodexHost.lnk
  -> wscript.exe
  -> C:\Users\hongfu\.codexhost-launch.vbs
  -> C:\Users\hongfu\.codexhost-launch.ps1
  -> %LOCALAPPDATA%\Programs\codexhost\bin\codexhost.exe launch
  -> ChatGPT.exe
  -> codexhost-shim.exe
  -> CodexHost runtime node.exe
  -> official codex.exe
```

The launcher snapshots seven HKCU environment values, writes temporary CodexHost launch values, and restores HKCU and `~/.codex/config.toml` after the Host shim exits. The desktop shortcut icon is `...\codexhost\bin\codexhost.exe,0`.

## Functional Evidence

- `hmharness` appeared in the enabled agent list and the renderer reported `ready`.
- The agent picker exposed `HMHarness` and the model catalog selected `glm / glm-5.3`.
- The HMHarness option rendered a dedicated base64 SVG image. Its source matched the bundled icon and did not use the Antigravity fallback asset.
- A real composer turn sent the exact marker `HMH_CODEXHOST_082_UI_FINAL_20260915_OK`.
- `run_20260914175429_9b60c1` completed in 15.451 seconds with `model=glm-5.3`, `outcome.success=true`, and `outcome.reason=final`.
- After the response, the composer was empty, visible `正在思考` count was `0`, marker text was visible, and no `hm-codexhost` process remained.
- After the final two-pass migration and placement reinstall, another clean shortcut launch returned HMHarness to `ready`, selected it for the mounted composer, exposed `glm / glm-5.3`, and rendered the same dedicated SVG on both the selected-agent button and the HMHarness option.

## Shutdown Restore

The shutdown test closed only the Codex Desktop main process. `codexhost-shim.exe` exited with it. The launcher then:

- removed `C:\Users\hongfu\.codexhost\windows-082-launch-fallback.json`;
- restored the original HKCU values for all tracked CodexHost variables;
- restored the original `CODEX_CLI_PATH` in `~/.codex/config.toml`;
- left no CodexHost shim injection in the config.

## Reproduction

```powershell
npm install -g @openai/codex@0.154.0
npm install -g @hmharness/codexhost-bridge@0.6.5
node scripts/apply-codexhost-0.8.2.mjs
node scripts/apply-codexhost-0.8.2.mjs  # idempotency
pwsh -NoProfile -ExecutionPolicy Bypass -File tools/install-windows.ps1
Copy-Item tools\launch-windows-0.8.2.ps1 $HOME\.codexhost-launch.ps1 -Force
```

Then launch through `Desktop\CodexHost.lnk`, select HMHarness and `glm / glm-5.3`, send one unique marker, and verify the run summary, final Thinking count, empty composer, dedicated icon, absence of an HM bridge child process, and HKCU/config restoration after shutdown.
