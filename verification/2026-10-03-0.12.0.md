## Official Boundary And Local Deltas

CodexHost 0.12.0 officially supports loading the plugin from the user plugin directory. The migration therefore keeps `~/.codexhost/plugins/hmharness` and `~/.codexhost/plugins/enabled.json` as the installation surface.

Two local deltas remain necessary:

1. The controller and renderer still contain hard-coded agent allowlists and model/ownership branches. The migration adds only the missing HMHarness anchors; it does not bypass the official plugin loader.
2. The renderer still gates locale catalogs behind remote Statsig controls. `--lang=zh-CN` changes the Chromium language but does not guarantee that the visible CodexHost catalog loads. The local i18n gate patch forces only the two CodexHost locale gates and is idempotent.

This is an official product boundary rather than evidence that the local plugin directory is corrupt. The upstream project has already declined to include HMHarness, so these deltas are maintained only in this user-owned backup repository.
